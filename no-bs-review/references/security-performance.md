# 安全与性能审查清单

> 随主技能加载，审查任何后端代码时读取。

## 安全清单（命中 → 🔴，除非有明确缓解措施并有注释说明）

| 项 | 审查要点 |
| --- | --- |
| SQL 注入 | 拼接 SQL；MyBatis `${}` 用在用户可控输入上（应改 `#{}`） |
| XSS | 用户内容未转义直接进 `v-html` / `innerHTML` |
| CSRF | 状态变更接口无 CSRF 防护 |
| 权限绕过 | 只靠前端隐藏入口，后端未校验权限 |
| 敏感信息泄露 | 密码 / token / 密钥出现在日志、异常信息、响应体中 |
| 文件上传 | 未校验类型、大小；存储路径用户可控 |
| 路径穿越 | 文件名 / 路径参数未清洗就拼进文件系统操作 |
| SSRF | 请求目标地址可被用户参数控制（可打内网） |
| 不安全反序列化 | 对不可信数据做反序列化 |
| 密钥硬编码 | 任何 secret 出现在源码里（skill 文件常被提交 git，同理适用） |

安全实现同样应该简单：如果一个安全修复让代码复杂度显著上升，先怀疑方案选错了。

## 后端性能已知陷阱（不需要测量，命中即报 🟡）

- 循环内查库或调远程接口（N+1）
- 无分页、无上限的全量查询
- 大数据量下嵌套循环做匹配（应先建 Map 再查）
- 事务内做远程调用或长耗时操作
- 新增查询未确认索引
- 一次性把大文件或大结果集读进内存

分级规则：有明确业务指标（响应时间、吞吐量、数据规模）时，超出指标属于正确性问题 → 升级为 🔴；没有指标时按 🟡 报告并注明触发条件。

前端性能陷阱（大列表虚拟滚动、深度 watch、重复请求）见 `frontend-review.md`。
