# TypeScript / Vue 审查细则

> 随主技能加载，仅在审查 TS / 前端代码时读取。

## TypeScript 类型复杂度

- discriminated union 允许使用，分支数 ≤ 5
- 以下默认避免，出现时先看是否有框架规范或明确需求支撑，没有 → 🟡：复杂 conditional type、嵌套 mapped type、复杂模板字面量类型、难以理解的 `infer`、Point-free、pipe/flow 函数组合
- **总判据：类型定义比业务代码更难懂 → 建议降低类型复杂度，宁可 `as` 断言加一行注释**。这不是妥协：类型是给人读的辅助线，变成主角就本末倒置了

## Vue 3

- 团队惯例：Composition API + `<script setup>`。选项式 API 的存量代码不报
- composable 抽取条件：逻辑 ≥ 2 处复用，或单文件已超 150 行。不满足就强行拆 → 🟡（过度设计）
- 隐式 watch 副作用没有注释说明触发条件和时机 → 🟡（读代码看不出会执行的机制都要说明）

## 前端性能与内存陷阱

以下命中 → 🟡；数据量或调用频率明确较大时 → 🔴：

- 大列表无虚拟滚动
- 深度 watch 大对象
- 短时间内重复发起相同请求（无防抖 / 去重 / 缓存）
- 未清理的副作用 / 内存泄漏：组件使用的 `addEventListener`、`setInterval`、全局事件监听等，在 `onUnmounted` 时未清理

为什么不用测量：都是被反复验证过的反模式，修复成本远低于排查成本。
